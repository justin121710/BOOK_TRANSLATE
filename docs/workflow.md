# 使用流程與後續工作

## 一次性設定

1. **iPhone Safari** 開 <https://justin121710.github.io/BOOK_TRANSLATE/>
   → 分享 → **加到主畫面**。之後一律從主畫面圖示開啟。
   （這不只是方便：以「網頁」形式使用時，iOS 可能在七天未開啟後清掉資料，
   加到主畫面的 PWA 可以豁免。）

2. 設定頁填兩把金鑰：
   - **Google Cloud Vision**：網站限制填 `https://justin121710.github.io/*`
     與 `http://localhost:5173/*`，API 限制只勾 Cloud Vision API
   - **翻譯**：選 Gemini 或 Claude。
     Gemini 金鑰請另外申請一把（[AI Studio](https://aistudio.google.com/apikey)），
     它無法套用網站限制，改用配額與花費上限保護

3. 按「測試金鑰」確認兩邊都通，再按「下載並快取字型」（約 17 MB，只需一次）。

## 每一本書的流程

```
新增書籍 → 匯入頁面 → 透視校正 → 辨識文字 → 檢查原文 →
翻譯 → 檢查譯文 → 圖片框 → 排版預覽 → 匯出 PDF → 備份
```

### 1. 匯入

| 來源 | 說明 |
|---|---|
| **拍書頁** | 盡量壓平、整頁入鏡、光線均勻。之後要逐頁拖四角校正 |
| **PDF** | 若帶原生文字層，會直接取用座標，**完全跳過 OCR、零 Vision 費用** |
| **相簿** | 已經拍好的照片批次丟進來 |
| **EPUB** | 走獨立路徑，重新編排成一本乾淨的中譯書。**分頁不會和原書一致，也沒有插圖** |

### 2b. 數學公式

**獨立成行的方程式**：在圖片框編輯器裡框起來，按「切換為方程式」（框會變紫色）。
方程式框**整塊原樣貼回**，裡面的文字連翻譯都不會送出去——動到任何一個符號都是錯的。

**行內的符號**（夾在句子裡的 `F_max`、`x²`、`σ`）：辨識時會自動偵測，
從原書裁下那一小塊當成內嵌圖片，形狀像素級精確。

判定刻意訂嚴——要「由英數字構成」**而且**至少符合一項：偵測到上標或下標、
含運算子、含希臘字母。所以 `1923年`、`PDF`、`第3章` 不會被誤切成圖片。
代價是沒有上下標又沒有運算子的單純變數（例如單獨一個 `a`）會漏掉，
那種情況它就照一般文字處理。

原理上是把公式從原文抽走、換成 `⟦M1⟧` 這種記號送去翻譯，所以：

- 模型碰不到公式內容，不會把變數名當成日文去翻或改寫
- 記號要擺在中文的哪個位置由模型判斷。中文語序和日文不同，**公式的位置會跟著移動**，
  這是正確的。「維持不跑掉」指的是符號本身與上下標關係不變，不是頁面上的絕對位置
- 用「修正原文」編輯時**請保留 `⟦M1⟧` 記號**，刪掉那個公式就不會出現在成品裡

### 2a. 先畫圖片框（有插圖的頁一定要先做）

**這一步要在「辨識文字」之前。** 進單頁 → 圖片框 → 按「自動偵測」，再手動增刪。

框內的文字會被歸成**圖內文字**，匯出時**蓋掉原本的日文、把中譯寫上去**
（填色取自文字框四周的顏色，不是純白，所以在彩色插圖上不會留白斑）。

**事後補畫也可以**：匯出與預覽時會依當下的圖片框重新判定，不需要重新辨識。
先畫的好處是翻譯時模型會知道那幾塊空間有限，譯文會更精簡。

### 2. 透視校正（只有相機／相簿需要）

點縮圖進單頁 → 透視校正 → 拖四角對準書頁邊界 → 套用。
拖動時對角會出現放大鏡幫你對準。**歪的頁面直接辨識，重排後會整頁歪掉。**

### 3. 辨識文字

書籍頁按「辨識文字」。事前會顯示要花多少錢，並區分免費（原生文字層）與付費頁數。

### 4. 檢查原文

進單頁看區塊清單。每一塊可以：

- **修正原文** — 改 OCR 讀錯的字。換行代表原書斷行，會影響重排，請保留
- **設為段首縮排** — 偵測錯了可以手動改。中文會縮兩個全形字

翻譯時模型會**主動依前後文修正明顯的辨識錯誤**（字形相近的誤認、濁點掉了、
小字促音被讀成大字等），並按修正後的意思翻譯。改過的地方會在區塊下方以
「AI 判讀修正」標示出來，可以按「採用修正後的原文」把它寫回原文欄位。

修正是顯示出來而不是靜默套用的：你要看得到 OCR 原本讀到什麼、模型改成什麼，
才判斷得出這個修正該不該接受。

### 5. 翻譯

事前顯示模型、區塊數與估計花費。頁面**依序**處理，好讓專有名詞的譯法
跨頁累積並保持一致。EPUB 會在翻譯後自動依中譯重新分頁。

**跨頁的句子會自動一起處理**：當某頁最後一段沒有句號（代表話還沒說完），
下一頁開頭那一段會被借過來一起翻，讓模型看到完整的句子再下筆，
譯文則各自寫回自己那一頁。所以同一句話不會被翻兩次，也不會出現重複的段落。

### 6. 檢查譯文

每一塊可「重跑這一塊」，對話框會顯示 OCR 原文與現有譯文，
可附一句指示（例如「這是人名」「語氣再口語一點」）。

### 7. 圖片框（若步驟 2a 沒做或要補）

單頁 → 圖片框 → 按「自動偵測」，再手動增刪。
空白處拖曳新增、點框選取後拖角落調整。

**什麼時候畫都可以。** 匯出與預覽時會依當下的圖片框重新判定哪些文字在圖內，
所以辨識完才回頭補畫也會正常覆蓋，不需要重新辨識。
（先畫的好處只是翻譯時模型會知道那幾塊空間有限，譯文會更精簡。）

### 8. 排版預覽

單頁 → 排版預覽。左原頁右重排並排，下方列出縮過字級的塊數與最小倍率、
以及仍然放不下的塊數（畫紅框）。**看到什麼就會匯出什麼**，兩邊共用同一份排版結果。

### 9. 匯出 PDF

可勾選「附上原頁掃描對照」（奇數頁原文、偶數頁中譯，檔案變兩倍大）。

### 10. 備份

書籍頁按「備份」下載 zip。**請養成習慣**——瀏覽器存的東西不是可靠的保存。
還原在書櫃頁最下方的「從備份還原」，會建立成新的一本書，不會覆蓋現有資料。

## 已知限制

- **字型缺日文專用漢字**：Noto Serif/Sans TC 對繁中與假名覆蓋 100%，
  但缺日文新字體漢字（実測 19 字中缺 9 字：静桜峠渋変読対応帰）。
  譯文是繁中所以通常不受影響；匯出前會做缺字檢查並列出來
- **頁眉／頁碼／側標**從原圖裁切貼回，所以不會進 PDF 的文字層（無法搜尋）
- **圖片偵測是啟發式**，必然需要人工確認
- **圖內文字的覆蓋**取的是文字框四周的中位色。底色單純（對白框、招牌、單色底）
  效果很好；文字壓在複雜紋理或漸層上時，覆蓋的色塊仍會看得出來
- **行內公式是圖片**，不能搜尋也不能複製。分數、積分、矩陣這類二維結構
  不在偵測範圍內，請用方程式框整塊處理
- **EPUB 沒有插圖**，且分頁與原書不同
- **翻譯用的金鑰無法限制來源**（Gemini 與 Claude 皆然），只能靠配額與花費上限

## 尚未做、值得考慮的

依我認為的價值順序：

1. **拿真書實測後的調校**。目前所有驗證都用合成資料。真實的日文書一定會冒出
   沒預料到的狀況——直排偵測、欄序、振り仮名剔除的門檻值都可能需要依實際結果調整
2. **整本書的詞彙表檢視與編輯**。現在詞彙表是自動累積的，看不到也改不了。
   人名譯錯會整本錯，應該要能開一個清單修正並重跑受影響的頁
3. **翻譯品質 A/B 比較**。同一頁分別用 Gemini 與 Claude 翻，並排比對再決定用誰
4. **多欄版面**。目前一個文字塊就是一個矩形，遇到雜誌式的多欄穿插版面會亂
5. **表格**。`table` 這個分類有了，但沒有對應的重建邏輯，目前當一般文字排
6. **中斷與續傳**。批次處理可以關螢幕（有 Wake Lock），但關掉分頁就得重來；
   已完成的頁面不會重做，所以影響有限
7. **匯出 EPUB**。目前只出 PDF。中譯的 EPUB 對電子書閱讀器比較友善
